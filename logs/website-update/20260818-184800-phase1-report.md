## Palette — brown/cream brand identity

Replaced the placeholder neutral-ink/forest-green palette in
`tokens.css` with a warm espresso/cocoa/cream/ivory/sand/honey palette.
Semantic token **names** are unchanged (`--color-text`, `--color-brand-600`,
`--color-surface`, etc.) — every component already consumed tokens, never
literals, so this was a single-file change, per the architecture
`tokens.css` itself documented. One new semantic token was added,
`--color-accent-gold`, for the restrained gold accent (used in exactly two
places — see "Files changed" above — not the pervasive interactive
colour).

Contrast audited by relative luminance (WCAG's own formula, not
eyeballed — script used is recorded in this session's transcript, same
method the previous palette's `--color-ink-500` tuning comment used):

- Text on surface / surface-subtle: **15.0:1 / 13.5:1**
- Muted text on surface-subtle (documented tightest pairing): **5.37:1**
- Button label (on-brand) on brand-600 / brand-700: **8.03:1 / 11.73:1**
- Brand colour as link/text on surface / surface-subtle: **7.68:1 / 6.88:1**
- Badge text (brand-700) on badge tint (brand-100): **9.80:1**
- All of the above clear WCAG AA's 4.5:1 for normal text with margin.
- `--color-border` and `--color-accent-gold` are decorative/non-text and
  were tuned for the ~3:1 non-text/graphical-object guideline instead:
  **3.8:1** and **3.38:1** against the default surface respectively.
  `--color-border-subtle` stays intentionally faint (~1.3:1), matching
  the previous palette's equally-faint border-subtle — a decorative
  divider backed by `--shadow-sm`, never the sole boundary cue.

Full rationale and the exact contrast-checker method are in
`tokens.css`'s own file-level comment.

## Existing image-generation tooling — inspected, not modified

`~/mtm-assets/scripts/xai-image-edit.sh` (outside this git repository —
nothing under `apps/` calls or wraps it). Calls xAI's
`POST /v1/images/edits` (model `grok-imagine-image-quality`):

- Accepts 1-3 reference images (`-r`, repeatable) + a text prompt +
  output path; **already hard-caps at 3 references**, matching xAI's own
  documented limit — confirmed in the script's own validation
  (`[ "${#REFS[@]}" -le 3 ]`).
- Reads `XAI_API_KEY` only from the environment (never a CLI arg, never
  logged); **confirmed unset in this session's environment** — generation
  could not have been run even if it had been in scope.
- Preserves the raw API response to `<output>.response.json` before
  attempting to save, so a billed-but-failed-save never loses a paid
  generation (`--recover-response` replays with zero extra API calls).
- For 2-3 references, sends a bare array of data-URI strings (the
  correct, empirically-confirmed shape per the master library's
  `PRODUCTION_MANIFEST.md` Session 3 fix); falls back to a single
  reference automatically on any 4xx.
- All 136 already-approved single-character images (website poses,
  expressions, action poses) used this script with 1 reference each — the
  same 48 website-pose files this Phase 1 pass copied into the site.

**Not run.** No generation call — billed or diagnostic — was made this
session. Pair images (2 refs/call) and 3-member group scenes fit the
existing 3-reference ceiling directly; 4-member group scenes (2 of the 6
planned) do not and need an explicit design decision first (documented in
`groups/README.md`) — this matches, and does not relitigate, the open
item already flagged in the master library's own manifest.
